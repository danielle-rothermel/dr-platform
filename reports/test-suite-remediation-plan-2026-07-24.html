What design decisions guide implementation?

contracts
  • Concurrent pause stays supported. Re-verification found that _SkipPaused is reachable under READ COMMITTED when a control pauses between candidate selection and control locking. The implementation will add a real race test, not delete the branch.
  • CI PostgreSQL failure is already explicit. The fixture change adds local destructive-target safety and a fixture-level CI failure; it does not replace the existing workflow preflight.
  • Current vocabulary only. Historical negative-name assertions are removed and replaced with an explicit positive root export contract.
  • Behavior before implementation shape. New tests call public APIs where possible. Private helpers remain only where the behavior has no public seam and the structural constraint itself is the contract.
  • Concurrency asserts invariants. Tests accept either winner and prove one committed outcome, one attempt, or no stale overwrite; they do not depend on scheduler order.

How will changes be integrated and reviewed?

sequential merge
  1. Each agent runs focused checks against its dedicated PostgreSQL database and commits exactly once on its owned branch.
  2. The primary agent inspects every diff for scope, behavior, historical vocabulary, brittle sleeps, and accidental source changes.
  3. Commits are cherry-picked sequentially onto impl/01-boundaries; disjoint ownership should make conflicts exceptional.
  4. After integration, a read-only frontier reviewer performs one findings-first pass over the complete diff.
  5. The primary agent resolves supported findings, runs focused repeats for concurrency/recovery, then runs ruff, ty, and the full PostgreSQL suite.
  6. The primary agent commits any plan/integration amendments, refreshes local main if needed, restacks, and submits with Graphite.
